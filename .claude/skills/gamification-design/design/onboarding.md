# Onboarding Design & Time-to-Value

The primary purpose of Onboarding is to guide the user to their first **Win-State** ("Aha! Moment") while making them feel smart and competent.

## Core Rules for Onboarding

### 1. The 4-Second Rule
Within 4 seconds of entering an experience, the user must intuitively grasp what to do next without reading dense documentation.

### 2. Desert Oasis Design
Keep the interface clean during onboarding. Hide advanced options and highlight the single desired next action with high visual contrast.

### 3. Step-by-Step Interactive Tutorials
Never force users to read long text manuals before acting.
- **Rule:** Action → Immediate Success → Explanation.
- Guide users by doing, not by telling.

### 4. Scaffolding Competence (CD2)
Never make the user feel dumb during their first session.
- Keep initial friction near zero.
- Provide early "easy wins" to trigger positive dopamine response.
- Use **Beginner's Luck (CD1)** or accelerated initial progress bars to create momentum.

---

## Onboarding Checklist

- [ ] Is the "Aha! Moment" reached within the first 3 minutes of usage?
- [ ] Is the Progress Bar initialized with pre-filled progress (e.g., 20% complete for creating an account)?
- [ ] Are non-essential setup steps postponed until after the first Win-State?
- [ ] Does every action trigger immediate, gratifying visual/auditory feedback?
- [ ] Is cognitive friction minimized until the user has built emotional buy-in?
